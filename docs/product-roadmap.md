# AI 赚钱案例库 — 产品规划文档

> 版本: v1.0 | 更新: 2026-05-10

---

## 1. 产品愿景

**让每个普通人都能通过 AI 多赚一份收入。**

不是卖课，不是画饼。用真实的案例、可复制的步骤，让不会编程、不懂技术的人也能上手。同时让赚到钱的人愿意回来分享，形成"学习 → 实践 → 分享"的正循环。

---

## 2. 目标用户画像

### 核心用户：副业探索者

| 维度 | 描述 |
|------|------|
| 身份 | 宝妈、大学生、上班族、三四线年轻人 |
| 技术能力 | 基本为零。会刷抖音、会用微信，但没写过代码 |
| 痛点 | 想赚钱但不知道做什么；试过刷单/微商被骗过；觉得 AI 是高科技跟自己无关 |
| 心理 | 既想尝试又怕被骗；对"月入过万"将信将疑 |
| 行为 | 会在小红书/抖音搜"副业"，收藏一堆但没行动 |
| 触发点 | "这个看起来不难，我也能试试" |

### 二级用户：案例贡献者

| 维度 | 描述 |
|------|------|
| 身份 | 已经用 AI 赚到钱的普通人 |
| 动机 | 分享经验建立个人品牌；获得曝光和流量；纯粹想帮人 |
| 顾虑 | 怕写得不好；怕被抄袭；担心隐私 |
| 需求 | 简单的投稿流程；审核通过后有署名；能被读者认可 |

### 三级用户（未来）：深度读者

| 维度 | 描述 |
|------|------|
| 身份 | 经常访问、收藏、分享的用户 |
| 行为 | 每周来看新案例；评论互动；推荐给朋友 |
| 价值 | 传播裂变的核心群体 |

## 3. 核心价值主张

| 竞品/替代方案 | 他们的弱点 | 我们的优势 |
|--------------|-----------|-----------|
| 知识付费课程（199元卖课） | 割韭菜的多，买完吃灰 | **免费 + 真实案例** |
| 小红书/抖音碎片化分享 | 不系统，东拼西凑 | **结构化教程 + 完整步骤** |
| AI 工具官方教程 | 太技术，普通人看不懂 | **大白话 + 场景化** |
| 自己做副业摸索 | 试错成本高，容易放弃 | **照着做就行，降低门槛** |

一句话差异化：**不讲大道理，只给能跟着做的步骤。**

## 4. 成功指标（OKR）

### 北极星指标：**月度活跃读者数**

指每月至少访问网站 2 次的独立用户。

### 分阶段目标

| 阶段 | 目标 | 关键结果 |
|------|------|---------|
| V1.0 上线 | 验证产品价值 | 上线后 30 天内累计 1000 UV；案例平均阅读完成率 > 60%；后台 CRUD 顺畅 |
| V1.2 社区 | 验证用户贡献 | 月投稿 > 10 篇；投稿审核通过率 > 70%；读者互动率（收藏/分享）> 5% |
| V2.0 增长 | 建立增长飞轮 | 月活 > 1 万；自然搜索流量占比 > 40%；老用户月留存 > 30% |

## 5. 用户旅程地图

### 核心流程：发现 → 阅读 → 行动 → 分享

```
发现案例      阅读详情       动手尝试       回来分享
  │             │             │             │
  ▼             ▼             ▼             ▼
搜索/推荐 → 浏览案例列表 → 打开详情页 → 看步骤/工具 → 跟着做 → 赚钱了 → 提交案例
  │                                                    │
  └── 分类筛选 ── 搜索 ── 排序 ──                   没做成 → 看别的案例
```

### MVP 阶段的用户关键路径

1. **新用户到达** → 看到 Hero 标题和简介 → 3 秒内理解"这是什么"
2. **浏览案例** → 看到案例卡片 → 被某个标题吸引 → 点击查看详情
3. **阅读详情** → 看痛点/解决方案/收入 → 看到具体步骤 → 看到所需工具
4. **决定尝试** → 收藏/保存 → 按步骤操作
5. **（未来）提交案例** → 点击"分享你的经验" → 填写表单 → 后台审核 → 发布

## 6. 分阶段发布计划

### V1.0 — 最小可用产品（现在 - 2 周）

**目标**：一个能访问的案例浏览网站，管理员能管理内容

**功能范围：**

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 首页 | Hero + 统计数字 + 案例推荐 + 关于我们 | P0 |
| 案例浏览 | 卡片列表 + 分类筛选 + 排序 + 搜索 | P0 |
| 案例详情 | 完整信息 + 步骤 + 工具 + 小贴士 | P0 |
| 管理后台 | 登录 + 案例列表 + 新增/编辑/删除案例 | P0 |
| 部署上线 | 前端 Vercel + 后端 Railway + 数据库 Atlas | P0 |

**不做的：**
- 用户注册/登录
- 投稿功能
- 评论/点赞
- 数据分析
- SEO 优化

**上线检查清单：**
- [ ] 网站能在手机和电脑正常打开
- [ ] 6 个案例数据完整显示
- [ ] 筛选/搜索/排序正常
- [ ] 管理员能登录后台
- [ ] 管理员能增删改案例
- [ ] 页面加载速度 < 3 秒
- [ ] 没有明显的样式问题

---

### V1.1 — 体验增强（第 3-4 周）

**目标**：提升阅读体验，让内容更容易被发现和分享

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 案例分页/加载更多 | 案例超过 20 个时优化加载 | P1 |
| 标签系统 | 多标签分类（不仅限于单分类） | P1 |
| 阅读量统计 | 展示热门案例 | P1 |
| 分享功能 | 生成分享卡片/链接 | P1 |
| 加载状态优化 | 骨架屏/加载动画 | P2 |
| 404 页面 | 友好提示 | P2 |
| SEO 基础优化 | 页面标题/描述/结构化数据 | P1 |

---

### V1.2 — 社区投稿（第 5-6 周）

**目标**：让用户能贡献内容，形成 UGC 雏形

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 用户投稿表单 | 填写案例基本信息 + 步骤 + 工具 | P0 |
| 后台审核流程 | 审核/驳回/编辑投稿 | P0 |
| 贡献者署名 | 案例页显示"投稿人" | P1 |
| 投稿状态通知 | 审核通过/驳回通知 | P2 |
| 简单注册系统 | 邮箱注册 + 投稿人身份 | P1 |

**关键决策：**
- 投稿是否需要注册？ → **建议需要注册（防垃圾投稿）**
- 审核流程：自动还是人工？ → **人工审核（保证质量）**
- 投稿人能否编辑已发布的案例？ → **不能，需联系管理员**

---

### V2.0 — 增长引擎（第 7-10 周）

**目标**：建立流量增长机制

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 案例合集/专题 | 按主题打包（如"新手必看的 5 个案例"） | P1 |
| SEO 全面优化 | 每个案例独立 URL + 结构化数据 + sitemap | P0 |
| 邮件订阅 | 新案例上线通知 | P1 |
| 热门案例排行榜 | 按阅读量/收藏量排序 | P2 |
| 社交裂变 | 分享得积分/激励 | P2 |

---

### V2.1 — 商业化探索（第 11-12 周）

**目标**：验证收入模式

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 精选合集付费 | 高价值案例打包（9.9 元） | 实验 |
| AI 工具推广链接 | 文中推荐工具挂 affiliate 链接 | 实验 |
| "请作者喝咖啡" | 用户打赏贡献者 | 实验 |

**原则**：所有商业化功能以 **不影响核心阅读体验** 为前提。免费内容永远占 80% 以上。

## 7. 功能优先级矩阵（MoSCoW）

```
P0 - 必须有（上线必备）
├── 案例浏览（列表 + 详情）
├── 分类筛选
├── 搜索
├── 管理员登录 + CRUD
└── 响应式（手机能用）

P1 - 应该有（体验完整）
├── 分页/加载更多
├── 阅读量统计
├── 用户投稿 + 审核
├── 分享功能
└── SEO 优化

P2 - 可以有（锦上添花）
├── 标签系统
├── 邮件订阅
├── 热门排行榜
└── 投稿人注册

P3 - 这次不做（未来再说）
├── 评论系统
├── 点赞/收藏
├── 付费合集
├── 用户个人主页
└── 数据分析面板
```

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 案例数量增长慢 | 高 | 中 | 前期自己整理 + 鼓励投稿 + 生成一部分 |
| 投稿质量差 | 中 | 高 | 人工审核 + 提供模板 + 编辑润色 |
| 用户来了不转化 | 中 | 高 | 优化案例质量 + 降低行动门槛 |
| 被抄袭/搬运 | 中 | 低 | 内容本身是壁垒，不怕抄 |
| 无收入持续运营 | 低 | 中 | 低成本运行（Vercel + Atlas 免费层） |

## 9. 发布节奏原则

```
每一次发布应该满足：
1. 用户能感知到变化（不是修了个 bug）
2. 功能是完整的（没有"开发中"的占位符）
3. 手机和电脑都能用
4. 老功能没有 regression

发布节奏：
V1.0 → (2周) → V1.1 → (2周) → V1.2 → (2周) → V2.0
        每次发布后观察 3-5 天数据再决定下一步
```
